# TOKYO GOURMET LOG — App Store公開・運用費・収益化計画

更新: 2026-11-18（公開までの期間は推定であり納期保証ではない）

## 目的とリリース境界

**MVP（初回公開）**: 店舗を探す→行きたいに保存→訪問記録→マイマップ→本人だけのクラウド同期、招待制グループ（2人以上のE2Eを通したもの）。任意の写真付き投稿や友達フィードは安全条件を満たせた場合のみ追加。

- 一般公開の街フィード、匿名ランキング、Sway型のすれ違いは初回公開に必須ではない。
- App Storeへは単にWebサイトを包むだけでなく、実用的なiOS体験が必要。ガイドライン4.2を参照。
- iPhoneを操作できない間でもGitHub・Supabaseの監査、設計、画面実装は進められる。実機署名・認証・通知・購入などの検証は本人の端末/開発アカウントが必要。

## 技術方針

既存の単一HTML＋JavaScriptを生かし、第一候補を **Capacitor + iOS（Xcode）** とする。先に最小のiOSシェルを検証し、審査面で不十分なら画面/UIやネイティブ連携を強化する。

1. GitHub PagesのPWAは引き続き維持。
2. iOSアプリのソース/静的アセットを同一リポジトリで管理。CapacitorのiOSビルドにはmacOSとXcodeが必要。
3. iOSのWKWebViewとSafariはストレージが異なるため、従来のlocalStorage/IndexedDBが自動移行されると扱わない。JSONと写真のバックアップ／インポート手順を用意。
4. Supabaseのメール認証リダイレクト（アプリ復帰時）、カメラ/写真許可、位置情報の説明、共有シート、オフライン動作を実機で検証。
5. 位置情報はユーザー操作時のみ取得。バックグラウンド位置追跡は初回公開対象外。
6. Supabaseは現在既存音楽アプリと同じプロジェクト/認証基盤を共有。**ユーザーのアカウント削除を実装する前に、サービス間のアカウント/データ分離を設計**。特に別アプリのデータを誤削除しない。
7. OAuth等が将来追加された場合はAppleのログイン規則を再チェック。現状のメールOTPの方式でも、認証フロー実機検証は必須。

## フェーズ別ロードマップ（推定）

| 時期の目安 | フェーズ | 完了判定 |
|---|---|---|
| 第1〜2週 | データの安全性 | 保存/端末間取り込み、招待/投票、権限分離の実機E2E、アカウント分離方針 |
| 第2〜4週 | iOS変換プロトタイプ | XcodeでiPhone起動、認証復帰、写真/位置情報、共有、ストレージ移行確認 |
| 第4〜6週 | App Store必須対応 | プライバシーポリシー、サポート窓口、アカウント/データ削除、RLS・通報/ブロックの最低要件 |
| 第6〜8週 | TestFlight/審査 | アイコン、スクリーンショット、説明、審査用ログイン、実機テスト、初回審査提出 |
| 第9〜20週 | 完成度の高い一般版 | 友達の承認、写真フィード、投稿管理、利用者検証、繰り返し改善 |

簡易の限定機能版は4〜8週間、写真投稿/友達フィードまで整えるなら3〜5か月を計画値とする。審査通過は保証できず、不具合や外部審査で延長する。

## Apple審査で注意すること

- ガイドライン1.2: ユーザー投稿を扱う際、問題投稿への対処、通報、ブロック、適切な管理が必要。
- ガイドライン4.2: 単純なWebラッパーでは不十分と判断され得る。iOSに合わせた使い勝手と機能が必要。
- ガイドライン5.1.1: 公開プライバシーポリシー、説明できるデータ収集、アプリ内アカウント削除の導線が必要。
- 審査用アカウント/操作説明、コンタクト先、スクリーンショット、年齢レーティング、App Privacy申告を準備。
- 課金する場合は対象地域のデジタル機能向けアプリ内課金規則と、日本の最新の決済オプションを確認。
- **公開可能な本人用サポートメール/窓口を確定するまでは、プライバシーポリシーを完成と見なさない。**

## 経費の目安（概算）

| 項目 | β段階 | 小規模の一般公開 |
|---|---|---|
| GitHub Pages | 無料枠を利用 | 利用条件/トラフィックに注意 |
| Apple Developer Program | 年99米ドル（現地通貨相当） | 毎年更新 |
| Supabase | Free $0/月、ただし非アクティブ時の一時停止あり | Pro $25/月〜（容量・転送等超過は別） |
| 写真ストレージ | Free 1GB、転送5GB（含まれる枠は種類別に確認） | Proの枠内または追加容量・転送費 |
| 地図・店舗検索 | OSM/OpenStreetMap公共系の限定的な試作 | 正式な提供元/APIや商用タイル契約へ移行 |
| メール・独自ドメイン | 当初は不要の可能性 | 需要と品質に応じて追加 |
| 通報/問い合わせ対応 | 開発者の手作業 | 利用人数と投稿数に比例して人的負荷増大 |

円建ての家計予算では、Apple年会費を年1.5〜2万円程度の仮置き、Supabase Pro $25を月4千円前後の仮置きとして試算する（為替レートを保証するものではない）。
「無料枠中心のβ」は月額インフラ0円に近くできるが、App Store公開後は年会費・保守作業・モデレーション費が別途必要。
小規模公開時の現金支出の**計画予算**は月5千〜2万円、写真・外部店舗APIの利用拡大後は月2万〜10万円以上もあり得る。これは固定料金の見積ではなく、利用量しだいの管理用予算である。

**費用リスク**: 写真が増えるとストレージだけでなく閲覧時の転送量が増える。画像圧縮とサムネイル、アップロード上限、レート制限、予算通知を設ける。Google PlacesはAPIのSKUによって単価・無料回数が異なるため、必ず開通前に試算する。

## 収益化: 段階的に検証

1. **ユーザー価値と継続利用**: 個人の記録と友人とのグループを無料で提供。初期は課金なし。保存数/来店記録/7日後継続/グループ招待成立などを個人特定なしで計測。
2. **店舗・予約・商品への送客**: 契約条件のあるアフィリエイト/送客プログラムを調査。予約成約等の成果に対する報酬であり、未契約の段階で収益を仮定しない。送客情報・広告/PR表記・店舗データ利用条件を明示。
3. **店舗向け掲載/PR**: 十分なユーザーと利用データが集まった後、PRと明示した店舗紹介やキャンペーン掲載を検証。ランキングを金銭で密かに操作しない。
4. **個人向けPro機能（任意）**: 記録の高度な分析、グループ管理の便利機能、コレクション整理等。個人の訪問記録やセキュリティを課金の人質にしない。
5. **B2B分析**: 匿名化だけで十分な保証にならないため、十分な件数と明確な同意を前提に慎重に検討。個人位置や訪問履歴を店舗へ販売しない。

### 売上の感度分析（実績・予測ではない）

Proを仮に**月390円**で販売し、対象手数料を総額15%（日本のSmall Business Program対象App Store手数料10%＋Apple決済処理5%の単純想定）とすると、税/返金/サポート/インフラ費を除いた1人当たりの回収額は月約331.5円。

| 月間有料ユーザー | 売上（税込等は未調整） | 手数料15%控除後 |
|---|---:|---:|
| 30人 | 11,700円 | 約9,945円 |
| 100人 | 39,000円 | 約33,150円 |
| 150人 | 58,500円 | 約49,725円 |

月5万円に相当する手数料控除後の収入には約151人の継続課金が必要（インフラ/税等は別）。MAUの3%が加入する仮定なら**約5,100人の月間アクティブユーザー**が必要。これは利用者獲得の難しさを示す試算で、実際の加入率を保証するものではない。

店舗向けPRを仮に5,000円/月で5店舗と契約した場合は月25,000円の売上（費用控除前）。実際には営業/広告効果の証明/表示義務/請求業務が必要。
