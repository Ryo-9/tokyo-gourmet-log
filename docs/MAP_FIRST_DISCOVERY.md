# TOKYO GOURMET LOG — マップ中心・発見フィードのUI（2026-11-19）

## 今回の方向性

- **地図**: iPhoneでの地図タブはほぼ画面全体を地図に使う。検索フォームと料理ジャンルは上部に浮かせ、下部にピンの店舗候補を横スワイプ表示する。
- **ホーム**: 機能を並べたダッシュボードをやめ、飲食店発見と個人の記録を主役にする。写真付きの「今日の一軒」→地図・友達・おまかせ→料理ジャンル→自分の訪問記録と行きたい店→詳しい検索、の順にする。
- Beliの食の発見フィード、Mapstrのピンで整理する導線、Swayの偶然の発見という体験から着想を得る。ただし画面の直接的な複製や、まだ存在しないSNS機能の偽装は行わない。

## 地図機能

1. 地図上の検索欄には駅・エリア・店舗名を入力できる。Enterまたは「探す」を押して初めてNominatimの地名検索に送信する。
2. 一致した候補の位置にマップを移動し、その中心近くでOpenStreetMapの店舗を明示的に検索する。結果はタグや営業情報が欠ける場合があるため候補として扱う。
3. 地図移動後に「この範囲で探す」を押すと、画面中央（地図の中心）から指定半径500/1000/1500mで店舗を検索する。
4. 「現在地」を押したときだけブラウザの位置情報権限を求める。地図中心の検索はGPSを要求しない。
5. 初回に本人が**地図タブを開いたとき**、固定の東京駅周辺の地図中心でOverpass APIに1回だけ問い合わせ、初期ピンを表示する。本人の現在地は送らない。連続検索はAPI負荷を抑えるため15秒の間隔を設ける。
6. 周辺店のピン・候補カードを押すと店名、ジャンル/タグ、直線距離の目安を確認できる。保存する際は確認ダイアログを通して「行きたい」に登録する。
7. マイマップでは利用者自身が保存しており、**確認済み緯度経度があるお店のみ**位置ピンを表示する。初期登録の住所・座標が不明な店舗の位置を捏造しない。
8. 自分の店の位置登録、住所の候補検索は「保存したお店の位置を登録・管理」に折り畳んで残す。
9. OpenStreetMapの著作権・帰属表示は地図上の結果シートで隠れないように調整。追加の出典・サービスの利用制限を下部でも明示。

## ホームの体験

- 「今日の一軒」は登録店のうち未訪問を優先し、日付に基づき1軒を選ぶ。**ランキング・レビュー・AI推薦・実際の人気度ではない**。「登録店からひとつ」と明示する。
- 自分で登録した店舗写真があれば表示する。写真がなければシンプルな線画と「写真なし」を表示し、架空の料理写真は作らない。
- 自分の食べた記録を訪問日順に並べる。未記録の場合は最初の記録を促す。友達や不特定多数の架空投稿は挿入しない。
- 自分の「行きたい」店を横にスワイプする形式で表示する。保存がない場合は地図へ案内する。
- 料理ジャンルはアイコンを統一し、横スクロールで選べる。ホーム検索・詳細条件・下部ナビは維持する。
- 写真共有や公開フィードを将来追加する際は、公開範囲の同意、ブロック・通報・削除などの安全策を先に実装する。
