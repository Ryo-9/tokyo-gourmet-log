# TOKYO GOURMET LOG — GitHub Pages版

AIビルダーのクレジット不要で運用できる静的Webアプリです。

## 公開
1. GitHubに公開リポジトリ `tokyo-gourmet-log` を作成します。
2. このディレクトリのファイルをリポジトリのルートに配置します（ChatGPTのGitHub接続でアップロード可能）。
3. リポジトリの Settings → Pages → Build and deployment → Deploy from a branch → `main` / `/(root)` → Save。
4. GitHubの公開処理後、`https://<GitHubユーザー名>.github.io/tokyo-gourmet-log/` で開きます。
5. 今後はGitHubのファイルを更新するだけで自動公開されます。

## 注意
- 訪問履歴はブラウザ内の保存領域にあります。別ドメインからは自動移行されないため、旧サイトのJSONバックアップを取得して取り込んでください。
- 写真はブラウザ内の画像保存領域を使う設計です。JSONと別に写真のバックアップを取ってください。
- 未登録の店舗の画像を実店舗の写真として扱いません。地図とSNSの一部機能は外部サービスへのリンクを使います。
- リポジトリは公開です。APIキー、パスワード、個人の訪問記録や個人写真はGitHubへコミットしないでください。

## 無料の店舗発掘（2026-11-18）

- SNSタブ「画像・リンクからお店を探す」：画像内の日本語・英語をブラウザ内OCR（Tesseract.js、初回に外部CDNから言語データを取得）でテキスト化。既存店舗と照合、Googleマップで確認後に保存。
- Googleマップの通常URLから店名候補を抽出。短縮URL・TikTok・Instagramリンクだけでは、投稿内容から自動で店名特定できないため手動確認が必要。
- 地図タブ「230店舗以外も見つける」：本人が位置情報使用を押した場合のみ、OpenStreetMapのOverpass APIで周辺の登録店を表示。お店を選んで保存できる。
- OpenStreetMap© contributors, ODbL： https://www.openstreetmap.org/copyright
- 公共のOverpass APIは小規模の試作向け。アクセス制限、未登録店舗、営業情報の不備などがあり、東京の全店を網羅しない。
- 将来の全域検索・写真/営業時間/評価にはGoogle Places API等の正式なデータ連携（課金・利用規約・APIキー保護）が必要。Googleの地図・店舗情報を一括収集して保存しない。
- 既存の `localStorage` 店舗・行きたい・訪問データと IndexedDB写真はそのまま維持。バックアップは定期的に取得。

## 友達・グループ・SNS共有（2026-11-18）

- 下部「つながる」タブに **友達と共有 / 今日のひと皿 / SNSクリップ** の3画面を追加。
- 自分で選んだ最大12店舗の「マイコレクション」を作成・端末保存、URLフラグメントに含めたスナップショットをLINE・SNS・メッセージで共有（サーバー不要）。共有には店名・区・ジャンル・リストの説明のみ使用し、訪問履歴・位置情報・自分の写真は含めない。
- 友達から受け取ったリストを閲覧・保存し、各店舗を「行きたい」に追加。投票は受取人の端末内で記録し、「投票結果を送る」でテキストとして返信する。**リアルタイム集計ではない**。
- 自分の写真と選んだ店舗名・コメントからシェア用PNGカードを端末内で生成し、Web Share APIから明示的にシェアまたは画像を保存。無断公開・無断投稿はしない。
- コレクションのJSONバックアップは「設定」画面に追加（既存店舗・訪問記録のJSONとは別）。
- **現在はメールログインと招待制オンライン・グループがβ実装済みです。友達申請、グループチャット、匿名ランキング、一般公開のアプリ内投稿フィードは未実装。** GitHub Pagesは静的ホスティングのため、実際の多人数プラットフォームへの拡張には認証・バックエンド・投稿/通報/ブロック/モデレーション・プライバシー設定が必要。
- 公開リンクは暗号化された非公開ページではなく、URLを知っている人なら閲覧可能。秘匿性の高い情報を含めない。

## 地図・訪問記録の統合（2026-11-18）

- 地図タブをLeaflet + OpenStreetMapの地図UIへ更新。初回の地図表示には外部ライブラリとOSM地図タイルの通信が必要。
- 「食べたい料理」を先に選び、その後「現在地から検索」を押す方式。ジャンル：すべて、ラーメン・麺、カフェ、焼肉・肉、寿司、スイーツ、カレー、酒場・バー。OpenStreetMapのタグで絞るため、未分類・タグ欠落の実店舗は検索に出ない可能性がある。半径500/1000/1500m。距離は道路距離ではなく直線距離。
- 位置情報の取得はユーザーが押した検索時のみ。取得地点はアプリの永続データに保存しないが、検索のためOverpass APIに座標が送信される。
- マイマップ：端末内の「訪問済み」・「行きたい」店舗のうち、確認できた座標を持つものだけ地図ピンに表示。ピンを押すと最後の訪問日、訪問履歴件数、店舗詳細へのリンクを表示。訪問済みでも日付が未記録なら「訪問日は未登録」と明示。
- 初期230店舗には正確な座標がない。店舗を選び地図上をタップして手動登録、またはNominatimでユーザー操作ごとに検索した候補の位置を**本人が確認してから**保存できる。自動的に偽の位置を生成しない。Nominatim公共サービスは最大1回/秒のポリシーなど制約があるため、検索は明示操作時に限定。候補が出ない場合は地図上の手動指定を利用。
- 地図で発見した店舗を自分の行きたいリストへ追加可能。既存のJSONバックアップの data.mods または data.custom に確認済み緯度経度を保存するため、以前の記録と一緒に移行できる。
- 利用した位置は他のアプリユーザーとは共有されない。OSMタイルの無断一括ダウンロードやオフライン地図キャッシュはしない。
- Sway型の「近くの人の最近のグルメ・すれ違い」は**未実装**。一般公開フィードやリアルタイム位置共有には、本人が投稿ごとに公開範囲を選べるアカウント・サーバー・通報/ブロック・位置の粗粒度化・投稿時刻の遅延とプライバシー対策が必要。

## クラウドログイン・手動同期β（2026-11-18）

- 下部のホームから歯車「設定」→「自分のグルメ記録をクラウドで管理」で、Supabaseのメールログインができる。初回にログイン用メールが届く。
- Supabase Auth Redirect URLに `https://ryo-9.github.io/tokyo-gourmet-log/` を利用者が登録済み。Site URLは既存音楽アプリのため変更していない。
- 公開用の **publishable key** のみを `cloud-config.js` に配置。サービスロールや秘密鍵は含まない。Supabase JS 2.119.0を設定画面を開いたときだけ動的読み込み。
- ログイン後「ローカル記録をクラウドへ保存」を押すと、バックアップJSONを保存してから行きたい店・訪問履歴を明示アップロード。client_idで重複防止。ローカル記録は消さない。
- 「クラウドから取り込み確認」で対象件数をプレビューし、「未登録分をこの端末に取り込む」で既存の端末記録を上書きせず不足分のみ追加。取り込む前にバックアップJSONをダウンロード。
- 「クラウド記録をJSONで取得」でクラウド側からバックアップを取得できる。
- **これはβ版の手動同期。常時リアルタイム同期ではない。** 端末間で変えた内容は各端末から明示的にアップロード/取り込みする必要がある。競合時はアップロードが同一IDのクラウド値を上書きするので、別端末での編集内容が変わる場合がある。
- 写真のIndexedDB、SNS未特定リンク、共有コレクションはまだ同期対象外。移行前に既存のデータJSONと写真を別々に保存する。
- 既存ローカル記録のキーは従来通り `tokyo-gourmet-log-v1`、クラウドの空アカウントによってローカル記録は削除されない。
- 認証メールと初回ログインは実機確認済み。クラウド書き込み・2ユーザーの権限分離の実機テストは未完了。公開前のβ運用として扱う。

## 招待制オンライン・グループ（2026-11-18）

- 「つながる」→「グループ」にオンラインの招待制グループβ版を追加。以前のログイン不要の共有リストはそのまま利用可能。
- Supabase Authでログインしたユーザーが、グループ作成・店候補登録・投票・友達への招待・退会・作成したグループの削除を行える。招待は相手から受け取ったユーザーコード（UUID）を使い、本人が承認して初めて参加する。名前・メールから不特定多数を勝手に探す機能はない。
- グループ候補には店名・区/エリア・ジャンルのみを共有。個人の訪問日・記録・写真・現在地・正確な位置履歴は自動共有しない。
- バックエンドは `tgl_groups`, `tgl_group_invitations`, `tgl_group_members`, `tgl_group_places`, `tgl_group_votes`。5テーブル全てRLS有効、19ポリシー、anonはSELECT不可。
- RLSのSQLトランザクション検証を3つの認証IDで実施し、招待承認前の参加拒否・承認後の参加・グループ外の閲覧拒否・作成者による投票確認をテスト。試験データはROLLBACKで残していない。詳細は `docs/GROUP_SECURITY_TESTS.md`。
- β版は「更新」ボタンで最新候補・投票を取得する。無条件のリアルタイム通知・チャット・一般公開フィード・すれ違い検知は未実装。
- 別々の実機での招待・承認・投票のE2Eテストは未完了。公開機能は少人数で先に試し、利用者を増やす前に招待の取り消し・強制退会・通報/ブロックを追加する。

### グループの使い勝手改善（2026-11-19）

- ログイン中の「グループ」画面で自分のユーザーコードを「友達に送る」からOSの共有画面へ送れる。共有画面が使えない場合はコピー、Clipboard APIも使えなければ選択・コピー用の表示に切り替える。共有は本人のボタン操作時のみ。
- 自分の「行きたい」「訪問済み」の保存店から、グループ候補フォームの店名・エリア・ジャンルを入力できる。未保存の初期店は候補リストに出さない。
- 選択だけでグループへの送信は行わず、「候補を追加」を明示的に押した場合のみ候補登録する。個人の訪問日・メモ・評価・写真・現在地は送信しない。
- NodeのUI動作・プライバシー回帰テストをGitHub Actionsで実行。実際の2端末E2E検証は未完了。
